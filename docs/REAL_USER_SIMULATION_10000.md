# OLYA AI — симуляция 10 000 реальных пользовательских сессий

Цель: ловить регрессии скорости, маршрутизации, поиска, памяти, качества ответа и клиентского UX до выпуска изменений.

## Панель

10 000 синтетических сессий строятся из 100 канонических пользовательских задач, 20 профилей пользователей и 5 способов ввода.

Профили включают обычных пользователей, родителей/домохозяек, подростков, школьников, студентов, пожилых, офисных сотрудников, предпринимателей, маркетологов, SMM/SEO, программистов, системных администраторов, дизайнеров, фрилансеров, продавцов маркетплейсов, HR, бухгалтеров и путешественников.

Варианты ввода: исходная формулировка, вежливая, мобильная без пунктуации, разговорная (`щас`, `слушай`) и зашумлённая (пробелы/emoji). Это намеренно проверяет не только идеальные benchmark-prompts, но и реальные формулировки.

## Что проверяется для всех 10 000

- instant utility против ненужного LLM;
- structured provider против общего web-search;
- актуальность и необходимость web;
- atomic stable facts;
- обычный direct LLM;
- practical web synthesis;
- follow-up/context;
- cross-chat memory;
- long-form budget;
- ложные web-trigger'ы в переводе/редактировании;
- естественные варианты русского языка.

Команда:

```bash
docker compose exec -T app python -m scripts.real_user_routing_audit_10000
```

Release-gate требует нулевого расхождения с ожидаемым маршрутом.

## Live-проверка сайта и нейросети

Live runner создаёт изолированные временные аккаунты, проверяет `/app`, auth, список чатов, память и настоящий SSE `/v1/chat/stream`. Он измеряет TTFT, полное время, длину ответа, web/source usage, размер compiled prompt, transport/runtime errors, утечки внутренней модели, неожиданные CJK-символы и лишние critic/repair inference passes.

Из-за одного CPU inference-slot полный live-прогон 10 000 генераций является endurance-тестом и может занимать много часов/суток. Для ежедневной проверки используется стратифицированная live-выборка из 500 сессий с ограниченным числом дорогих long-form генераций; маршрутизация всех 10 000 всё равно проверяется полностью.

```bash
bash scripts/run_real_user_simulation_10000.sh
```

Полный endurance run:

```bash
bash scripts/run_real_user_simulation_10000.sh --full
```

JSON и Markdown отчёты live-прогона сохраняются в `/tmp/olya-real-user-10000-*.json` и `/tmp/olya-real-user-10000-*.md` внутри контейнера.

## Уже найденные этим подходом классы дефектов

- версии ПО и даты релизов могли использовать устаревшую память модели;
- current-role intent был слишком узким;
- `что такое курс валют` ошибочно включало web;
- `что нужно знать, чтобы...` ломалось из-за запятой;
- русские склонения и `10 000 символов` не всегда включали long-form;
- первое memory-вопрос-сообщение нового чата не получало cross-chat memory;
- self-contained rewrite мог зря тянуть историю/искать слова `вчера/сегодня` из исходного текста;
- `ещё варианты`, `короче`, `подробнее` могли терять предыдущий контекст;
- `щас`, `почём`, `подскажи пожалуйста` и другой естественный язык ухудшали routing;
- локальное время и простая арифметика могли необоснованно занимать LLM slot;
- рекомендации по актуальным товарам требовали отдельного fresh-shopping intent.

Эти классы должны оставаться regression tests при дальнейшей разработке.
