# Sprint 44 — Scope Lock / Instruction Adherence

Дата реализации: 2026-09-07.

## Цель

Не позволять модели самовольно расширять задачу пользователя: переписывать вместо точечной правки, добавлять непрошенные разделы, сокращать материал, писать пояснения при запросе «только результат» или нарушать требуемый формат.

## Архитектура

`latest user message -> deterministic Scope Compiler -> request-local ScopeContract -> prompt guard -> Qwen -> deterministic scope audit -> conditional repair`

Дополнительный LLM-вызов для компиляции Scope Contract не используется. Это принципиально для 32-ГБ CPU/RAM-профиля.

## Какие ограничения распознаются

- «только готовый текст», «без пояснений/комментариев»;
- «ничего не добавляй», «не дополняй»;
- «не сокращай»;
- «не меняй структуру» / «сохрани структуру»;
- «не меняй смысл» / «сохрани смысл»;
- «не добавляй разделы/заголовки»;
- «не переписывай», «только исправь»;
- `только JSON`, `только HTML`, `только код`, таблица/список;
- базовые английские эквиваленты этих ограничений.

## Enforcement

1. `ContextCompiler` всегда компилирует Scope Contract из последнего пользовательского сообщения.
2. Контракт хранится в `ContextVar`, поэтому параллельные запросы пользователей не разделяют состояние.
3. Guard добавляется как системное сообщение, явно подчинённое core safety policy.
4. `AnswerQualityEngine` проверяет измеримые ограничения кодом.
5. Если Scope Lock нарушен, существующий Auto repair path получает внутренний harmless requirement sentinel и выполняет максимум один repair-pass.
6. Успешный ответ не запускает дополнительную Qwen-проверку.
7. Strict critic также получает нормализованный Scope Lock.

## Детерминированные проверки

- отсутствие непрошенного preamble;
- валидный JSON и базовый HTML-only contract;
- появление новых Markdown-заголовков;
- существенное самовольное расширение текста;
- существенное сокращение;
- грубое изменение количества абзацев;
- широкое переписывание вместо точечной правки через консервативный lexical-overlap gate.

Семантическое требование «не меняй смысл» не объявляется детерминированно доказанным: оно передаётся модели и critic, а quality report честно помечает его как `unverified`, если нет семантической проверки.

## Fail-open против ложных срабатываний

Если исходный материал нельзя безопасно выделить из запроса, эвристики длины/структуры не блокируют ответ. Scope guard продолжает действовать, а quality report показывает, что структурная часть не была доказана. Это предпочтительнее ложного repair правильного ответа.

## Regression coverage

`tests/test_sprint44_scope_lock.py` проверяет:

- русские edit-only ограничения;
- отсутствие false-positive на обычном открытом вопросе;
- инъекцию Scope Guard в context;
- final-only;
- no-expand/no-shorten;
- preserve-structure;
- JSON-only;
- подключение к существующему Auto repair;
- изоляцию ContextVar между async tasks;
- отсутствие дополнительного LLM-компилятора.

## Ограничение

При явном `verification=off` prompt-level Scope Guard остаётся активным, но постгенерационный quality/repair pipeline по существующему пользовательскому контракту отключён. В обычном `auto` (default) и `strict` Scope Lock получает deterministic enforcement и conditional repair.
